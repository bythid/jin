# Jin（锦）视觉主题规范

> 本文是 Jin 主题的设计规范与落地说明。控件库的组件规范、交互逻辑、API 与状态机不在此重复——
> 本文只讲视觉层，以及它如何落到令牌契约上。

主题 id：`data-jin-style="jin"`
模式：`data-jin-mode="dark"` = **玄锦**（标志性模式，库的默认）· `data-jin-mode="light"` = **素锦**

> **来源说明**：**Jin（锦）主题是原创设计**，也是本库的默认视觉身份。
> 另外八个风格（`minimalism-and-swiss-style`、`neumorphism`、`glassmorphism`、`claymorphism`、
> `flat-design`、`neubrutalism`、`brutalism`、`dimensional-layering`）是对
> [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
> 所收录风格的实现——该目录是本库"令牌必须覆盖形状/深度/动效而不只是配色"这一要求的来源。
> 我们实现的是各风格的**特征**，落在本库自己的 80 令牌契约上；该仓库提供的是设计指引而非 CSS，
> 因此没有复制其任何样式表。完整署名见 [CREDITS.md](../CREDITS.md)，八个风格各自的定位见
> [第八节](#八已实现风格清单)。

## 一、定位与设计原则

**一句话**：锦 = 经纬网格上的有限色盘提花 + 丝线光泽 + 金线点睛 + 循环纹样。
UI 转译 = 有秩序的高密度、有节制的华丽、清晰的主次层级、现代可读的东方织物质感。

六条落到实处的原则：

| 原则 | 在令牌/样式里的体现 |
| --- | --- |
| 繁而不乱 | 纹样只有一种：8×8 的经纬网格（`--jin-surface-texture`），以极低不透明度出现，且**只允许出现在背景、空状态、装饰性分隔** |
| 有秩序的高密度 | 4px 节奏的间距刻度；控件高度靠 `--jin-control-height-*` 收紧，**不压缩间距刻度**——压缩间距会牺牲触控目标 |
| 边界感 | 所有面板都有 1px 边框（`--jin-border-width`），日常边框是中性经纬线色；**金线只留给强边框与焦点环**——处处描金等于没有金 |
| 主次分层 | 地纹→背景、主纹→内容、副纹→次要信息、勾边→强调。对应 `--jin-bg/surface/sunken`、`--jin-text`、`--jin-text-muted`、`--jin-accent`+`--jin-focus-ring-color` |
| 庄重内敛精密 | 标题用衬线/宋体（`--jin-font-display`），正文用现代无衬线；圆角 6/8/12px；动效 150–250ms |
| 现代优先 | 对比度全部实测达标（见第六节），装饰不进入可读区域 |

**不是"古风皮肤"**：没有龙凤、没有祥云满铺、没有书法字、没有金箔贴图。只有织物被抽象成网格、细线、
克制色盘与方向性光泽。

## 二、色彩系统

### 有限色盘

不追求无限渐变，只用一组有语义的有限颜色：

| 角色 | 玄锦（深色） | 素锦（浅色） | 语义 |
| --- | --- | --- | --- |
| 地（背景） | `#12171d` 玄青 | `#f5f4f1` 绢白 | 现代中性底，只留一丝织物暖意 |
| 面（面板） | `#171e26` / `#1e2731` | `#faf9f6` / `#ffffff` | 抬升靠明度差 |
| 主纹（强调） | `#e0705a` 朱红 | `#b3402a` 朱红 | 主操作、当前项 |
| 信息 | `#6aa8cd` 石青 | `#2e6386` 石青 | 提示、链接 |
| 成功 | `#6cbd80` 石绿 | `#3f7a4c` 石绿 | 完成、可用 |
| 警告 | `#dda23f` 琥珀 | `#96601a` 琥珀 | 注意 |
| 危险 | `#e2706f` 朱红偏冷 | `#a8323c` 深朱红 | 删除、失败 |
| 金 | `#d8b54a` / `#9a7a14` | `#9a7a14` | **仅**焦点环、强边框、强调装饰 |

### 金线点睛：金色只占约 5%

金色**不用于小正文**，只出现在四个地方：

1. **焦点环** `--jin-focus-ring-color` —— 键盘可见焦点的唯一载体
2. **强边框** `--jin-border-color-strong` —— 只在需要"勾边点睛"的地方出现；日常边框
   `--jin-border-color` 是中性经纬线色，像织物里不抢戏的经线纬线
3. **装饰性分隔** —— 标签式分隔线两端淡入（`.jin-rule-thread` 或 `.jin-divider--labeled`）
4. **图标高光** —— 通过 `currentColor` 继承语义色，不单独硬编码

这条纪律是机械可查的：`tools/check_tokens.py` 会拒绝任何出现在主题层之外的十六进制颜色。

### 深底亮纹

深色模式下主纹比浅色模式**更亮**（`#e0705a` vs `#b3402a`），因为深底上的暗红无法作为文字或细线条阅读。
两个模式共用同一套语义名，但取不同的明度——这是色彩系统必须按模式分化、而不是简单反相的原因。

## 三、材质与质感

### 丝光（`--jin-surface-gradient`）

柔和、有方向性的光泽：一道自上而下的宽渐变，顶部略亮、底部略暗，模拟光从斜上方来。

```
玄锦：linear-gradient(180deg, rgba(236,234,228,.04) 0%, transparent 40%, rgba(0,0,0,.18) 100%)
素锦：linear-gradient(180deg, rgba(255,255,255,.5) 0%, transparent 40%, rgba(34,32,28,.03) 100%)
```

高光**细而窄**（40% 处收束），不是大面积发光——丝光是感觉到的，不是看到的。

另有按需启用的 `.jin-sheen`：一道 105° 的窄高光在 hover/focus 时扫过一次，像丝线反光。
它只在交互时播放，不会无人看管地跑动画；`prefers-reduced-motion` 下高光仍在，只是不再移动。

### 提花浮雕（`--jin-shadow-inset`）

轻微内凹：一道 `inset 0 1px 2px` 的浅内阴影。用于输入框、凹陷区。
**不是**重阴影，没有塑料感，也没有旧拟物风的高光亮边。

### 织纹（`--jin-surface-texture`）

8×8 的经纬网格，SVG data URI，以墨色（浅色）/ 米白（深色）绘制，约 5% 不透明度。
它只出现在三处：宿主显式标注的 `.jin-ground` 区域、空状态/未找到状态的图标底板、
以及（作为背景色的补充）装饰性分隔。**永不进入内容可读区域。**

### 金线（金色渐变）

金线不作为一个独立令牌，而是由两个契约令牌组合得出：

- 经纬线 = `--jin-border-color`（1px，中性线色——织物的骨架，不是金）
- 亮金线 = `--jin-border-color-strong`
- 焦点金 = `--jin-focus-ring-color`

分隔线两端淡入的渐变直接引用这三个令牌，所以换主题时金线的色相会跟着换。

### 圆角与阴影的克制

| | 值 | 说明 |
| --- | --- | --- |
| 圆角 | 6 / 8 / 12px（sm/md/lg），full = 胶囊 | 现代尺度，挺括而不生硬 |
| 外阴影 | 干净的弥散阴影，按层级加深 | 卡片用 elevation-1，极浅；浮层用 elevation-3/4 |
| 内阴影 | 输入框、凹陷区 | 微浮雕，无高光亮边 |
| `--jin-blur` | `0px` | 玻璃拟态不属于 Jin |

## 四、纹样、排版、图标、动效

### 纹样系统

只用抽象化、几何化、骨架化的纹样。**本主题只实现了一种：经纬网格**（二方/四方连续的骨架形式）。
理由：一种纹样做到位，比五种纹样互相打架更接近"繁而不乱"。

主纹/副纹/地纹的层级由**不透明度**而非图案复杂度区分：

| 层级 | 载体 | 强度 |
| --- | --- | --- |
| 地纹 | `--jin-surface-texture` | 5–7% 不透明度 |
| 副纹 | 边框、分隔线 | 34–62% |
| 主纹 | 内容、强调色、焦点环 | 100% |

纹样一律 `aria-hidden`，不进入可访问性树。

### 排版

| 用途 | 令牌 | 字族 |
| --- | --- | --- |
| 标题（弹窗、抽屉、卡片、通知、结果页、警告框标题） | `--jin-font-display` | 宋体/衬线（Noto Serif SC → 宋体 → Georgia） |
| 正文与一切控件 | `--jin-font-family` | 现代无衬线（Inter → 系统 UI → 苹方/微软雅黑） |
| 代码、快捷键 | `--jin-font-mono` | JetBrains Mono → 等宽 |

**分工是刻意的**：`--jin-font-display` 只挂在真正的标题上。标签页、按钮、表单标签、键值表的名词
都留在无衬线字体——那些是界面器械，界面效率优先于仪式感。这个区分无法只靠令牌表达，所以在
样式表里划分（见 `src/styles/jin.css` 的 "titles take the display face" 一节）。

字距 `0.012em`、行高 `1.55`，字重只用 400/500/700 三档，避免粗细跳跃。

### 图标

线性、几何、单路径、`stroke` 走 `currentColor`——图标自动继承所在位置的语义色，不硬编码颜色。
图标尺寸以 `em` 为单位，跟随周围文字大小。

### 动效

| 令牌 | 值 |
| --- | --- |
| `--jin-duration-fast` | 150ms |
| `--jin-duration-base` | 200ms |
| `--jin-duration-slow` | 250ms |
| `--jin-easing-standard` | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| `--jin-easing-emphasized` | `cubic-bezier(0.16, 0.84, 0.24, 1)` |

轻、短、克制：不做弹跳、不做旋转、不做夸张缩放。

**两处机械动画是刻意的例外**：加载指示器的旋转与骨架屏的扫光使用固定时长，不随主题的
时长令牌变化。理由：把旋转时长设为 0 的转圈图标不再表示"正在工作"，反而丢掉了它唯一的职责。
`tools/check_tokens.py` 把这两处显式列入白名单。

`prefers-reduced-motion: reduce` 下所有时长令牌归零，丝光高光改为静态。

## 五、Design Tokens

### 与契约的对应关系

本主题**不新增令牌命名体系**，而是把上述设计意图逐条落到既有的 80 个契约令牌上
（完整清单见 [`contracts/tokens.json`](../contracts/tokens.json)）。对照表：

| 设计意图 | 契约令牌 | 说明 |
| --- | --- | --- |
| 地 / 面 / 凹陷 / 抬升 | `--jin-bg` `--jin-surface` `--jin-surface-sunken` `--jin-surface-raised` | 抬升靠明度差而非阴影 |
| 正文 / 次要 / 更弱 | `--jin-text` `--jin-text-muted` `--jin-text-subtle` | 三级全部实测 ≥ 4.5:1 |
| 强调色上的文字 | `--jin-text-on-accent` | 深色模式下是**深色**文字（见第六节） |
| 主色 / 悬停 / 按下 | `--jin-accent` `--jin-accent-hover` `--jin-accent-active` | 按下只作为填充使用 |
| 语义四色 + 其浅底 | `--jin-danger/warning/success/info` + `-text` + `-bg` | 每色三件套 |
| 经纬线边框 | `--jin-border-color` `--jin-border-color-strong` `--jin-border-width` | 宽度恒为 1px；金仅用于 strong |
| 金焦点环 | `--jin-focus-ring-color` `-width` `-offset` | **独立成组，不由 accent 推导** |
| 丝光 | `--jin-surface-gradient` | 方向性微渐变 |
| 提花浮雕 | `--jin-shadow-inset` | 内阴影 |
| 织纹 | `--jin-surface-texture` | 经纬网格 data URI |
| 克制圆角 | `--jin-radius-sm/md/lg/full` | 6 / 8 / 12 / 999px |
| 微抬升 | `--jin-elevation-1..4` | 干净弥散阴影，无高光亮边 |
| 无玻璃 | `--jin-blur: 0px` | 显式关闭昂贵效果 |
| 标题字族 | `--jin-font-display` | 本次为契约新增的唯一令牌 |
| 正文字族 | `--jin-font-family` | |
| 字距/行高/字重 | `--jin-letter-spacing` `--jin-line-height` `--jin-font-weight-*` | |
| 动效 | `--jin-duration-*` `--jin-easing-*` | |
| 层级 | `--jin-z-*` | |

### 为什么没有照搬 prompt 里的令牌名

prompt 第十节给了一组示意命名（`--jin-bg-deep`、`--jin-primary`、`--jin-surface-2`、
`--jin-border`、`--jin-radius` 等），并注明"仅作视觉方向参考"。落地时采用既有契约，原因有三：

1. **契约先行**：80 个令牌的名称、语义、类型已经冻结，全部 36 个组件与 6 个主题都按它书写。
   引入第二套命名会让每个组件面临"这个颜色该用 `--jin-primary` 还是 `--jin-accent`"的问题。
2. **机械可查**：`tools/check_tokens.py` 强制每个主题定义全部令牌、禁止硬编码颜色。
   多一套命名等于放弃这道检查。
3. **多主题共存**：`--jin-primary` 与 `--jin-accent` 表达的是同一件事，但 `brutalism` 与
   `dimensional-layering` 用的是后者的语义（强调填充 + 其上文字 + 悬停/按下三态）。
   保持单一命名，三个主题才能自由切换。

prompt 第十节的**设计意图已全部落地**：色值、圆角、双阴影、金色渐变都已转译为契约令牌，
其中金色渐变由 `--jin-border-color-strong` + `--jin-focus-ring-color` 组合表达（见第三节"金线"）。

### 为什么不提供 Tailwind preset

prompt 第十二节提到"Tailwind preset 方向"。**本库不使用 Tailwind**，因此不产出 preset，
原因不是偏好，而是它会与契约重复且冲突：

1. **令牌已经是运行时接口**。控件样式全部写 `var(--jin-*)`，主题在运行时通过
   `<html>` 上的两个属性切换。Tailwind preset 会把颜色在**构建期**固化进 class，
   换主题就要重新构建——正好丢掉"切换主题 = 替换一个属性"这个性质。
2. **会产生第二个事实来源**。同一组色值同时存在于 `contracts/tokens.json`、
   主题 CSS 和 `tailwind.config.js` 三处，`check_tokens.py` 只能校验前两处的一致性。
3. **本库不使用它**。样式全部是纯 CSS + 自定义属性，引入 Tailwind 会与令牌契约重复。

**如果应用自己用 Tailwind**，正确的接法是把令牌变成 Tailwind 能引用的运行时变量，
而不是把值复制进去——这样主题切换依然生效：

```js
// tailwind.config.js —— 只转发，不复制色值
module.exports = {
  theme: {
    extend: {
      colors: {
        jin: {
          bg: 'var(--jin-bg)',
          surface: 'var(--jin-surface)',
          text: 'var(--jin-text)',
          accent: 'var(--jin-accent)',
          // …
        },
      },
      borderRadius: {
        'jin-sm': 'var(--jin-radius-sm)',
        'jin': 'var(--jin-radius-md)',
        'jin-lg': 'var(--jin-radius-lg)',
      },
      fontFamily: {
        jin: 'var(--jin-font-family)',
        'jin-display': 'var(--jin-font-display)',
      },
    },
  },
}
```

关键是值写成 `var(--jin-*)` 字符串而非十六进制字面量。Tailwind 只负责生成
`bg-jin-accent` 这样的类名，真正的颜色仍由主题在运行时决定。

### 如何新增一个主题

```css
/* themes/my-style.css —— 必须定义全部 80 个令牌 */
:root[data-jin-style='my-style'] {
  --jin-bg: /* … */;
  /* … 其余 79 个 */
}
```

```bash
python tools/check_tokens.py    # 令牌完整性 + 无硬编码
python tools/check_contrast.py  # 对比度审计
```

把文件加入 Gallery 的 `gallery/src/main.ts` 与 `gallery/src/host/preferences.ts`，
即可在顶部切换器里看到它。

切换到新风格后，Gallery 的**令牌面板**会逐项显示该风格下的实际取值，任何缺失都会标为
`(missing — fallback in use)`——这是"主题文件是否完整"的可视化证明。
面板底部还会渲染 `.jin-ground`、`.jin-sheen`、`.jin-rule-thread` 三个装饰性工具类的实时效果，
因为纹样与金线这类令牌光看取值看不出对不对。

## 六、可访问性视觉

### 实测对比度

`tools/check_contrast.py` 逐主题审计，全部通过。关键数字：

| 检查项 | 玄锦（深色） | 素锦（浅色） | 要求 |
| --- | --- | --- | --- |
| 正文 on 背景/面板/抬升/凹陷 | 12.6 – 15.6:1 | 13.6 – 16.3:1 | ≥ 4.5 |
| 次要文字 on 四种表面 | 6.6 – 8.2:1 | 5.7 – 6.8:1 | ≥ 4.5 |
| 最弱提示文字 on 四种表面 | 4.8 – 5.9:1 | 4.8 – 5.7:1 | ≥ 4.5 |
| 强调色上的文字 | 4.9:1（按下）– 7.2:1 | 4.9:1（悬停）– 7.1:1 | ≥ 4.5 |
| 焦点环 on 四种表面 | 7.6 – 9.5:1 | 3.4 – 4.1:1 | ≥ 3.0 |
| 语义四色文字 on 各自浅底 | 5.9 – 6.3:1 | 6.1 – 7.3:1 | ≥ 4.5 |

### 三个刻意的决定

**1. 深色模式的强调色比浅色更亮，其上文字是深色。**
浅色模式的 `#b3402a` 放在深底上只有 2.6:1——作为白色文字下的填充尚可，作为文字或图标线条完全不可读。
所以深色模式把朱红提到 `#e0705a`，同时把 `--jin-text-on-accent` 从白色改为深色。
这是色彩系统必须按模式分化、不能简单反相的具体原因。

**2. 焦点环永远独立声明。**
`--jin-focus-ring-*` 在全部十八个主题文件里都显式定义，绝不由 accent 推导。
否则某个把强调色放得靠近背景的风格会顺手抹掉键盘焦点——一个由配色选择导致的可访问性事故。
Jin 的焦点环用金色：`#d8b54a`（深色，7.6–9.5:1）与 `#9a7a14`（浅色，3.4–4.1:1）。

**3. 颜色从不是唯一的信息载体。**
每个 tone 都配独立图标；进度条始终打印百分比；树节点的失败状态同时有图标、文字与重试按钮。

### 其他

- 焦点可见：`.jin-focus-ring` 与各组件的 `:focus-visible` 规则，从不 `outline: none` 了事。
- 金色不用于小正文（见第二节）。
- 装饰纹样 `aria-hidden`，不进入可访问性树。
- 默认深色玄锦；浅色素锦为可选模式。

## 七、禁止项（已在实现中规避）

| 禁止 | 现状 |
| --- | --- |
| 满屏大红大金、红金渐变、金箔贴图 | 金色限于焦点/边框/装饰，占比远低于 5% |
| 具象龙凤、祥云满铺、书法字做正文 | 唯一纹样是抽象经纬网格；正文为无衬线 |
| 低对比金色文字 | 金色不用于文字；所有文字对比度实测达标 |
| 复杂纹理干扰阅读 | 纹样仅出现在背景、空状态、装饰性分隔 |
| 过度圆角、过度阴影、过度发光 | 圆角 ≤ 12px；外阴影按层级克制加深；无 glow |
| 为"国风"牺牲清晰度和可访问性 | 对比度、焦点、非颜色信号三项均机械校验 |
| 定义具体控件/交互/状态机 | 本主题只碰令牌与装饰性 CSS |

## 八、已实现风格清单

本库发布 **9 个风格、18 个主题文件**：每个风格有浅色与深色两个文件，每个文件独立声明全部
80 个契约令牌。**Jin（锦）是原创**且为默认；另外八个风格是对
[ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 目录条目的实现
（署名见 [CREDITS.md](../CREDITS.md)）。

### 选择标准

目录共 88 条（其中 50 条标记为 active）。本批实现的是其中的**主流风格**：既是业界广泛采用的
那些，也是该目录自己的 product 与 UX 指引里被引用最多的那些。第二个条件同样重要——它们在契
约轴上互不重叠：`glassmorphism` 是 `--jin-blur` 的唯一使用者，`neumorphism` 是
`--jin-shadow-inset` 的唯一使用者，`claymorphism` 把"3px 描边 + 大圆角"推到极限，
`brutalism` 与 `flat-design` 分别把动效轴和深度轴归零。一个只换配色、不动形状与深度的风格，
证明不了契约里的任何一条。

### 三条跨风格约定

**1. 深色模式不是浅色模式的反相。** 每个风格的 `.dark.css` 单独调色：深底上的强调色要更亮、
其上文字往往反而要用深色（见第六节第 1 条），玻璃与黏土的深色版还要重建光源方向而不是取负。
这也是 `check_contrast.py` 逐文件审计、而不是只审浅色文件的原因。

**2. 半透明表面必须诚实声明它在什么底色上。** 玻璃风格的表面写成"深色底上的 rgba"，而不是
"8% 的白"。两者渲染结果相同，但只有前者能被正确测量——白色的 rgba 三元组在任何对比度审计里都
是白色，那样的通过是假的。

**3. 浮动层的材质只有一处定义。** 基础样式表把 `--jin-surface-translucent` 与 `--jin-blur` 用在
菜单、浮层、对话框、抽屉、通知这些**漂浮在内容之上的表面**。非玻璃风格把两个值与 raised 面板
取齐、blur 设为 `0px`，因此渲染与从前完全一致；只有玻璃风格需要一个说得出材质的去处。
气泡提示（tooltip）是唯一例外：它用 `--jin-text` 作为底色，半透明的"墨"是读不出来的。

### 目录里还没有实现的部分

Landing Page、BI / Analytics、Mobile 三组描述的是**页面结构与信息密度**（首屏、看板、移动端
导航），不是控件的视觉语言，落在令牌契约能表达的范围之外。Platform/System 组（Fluent 2、
Polaris、Spectrum 2）本身是一整套设计系统，要落地需先决定把它的哪一部分映射到 80 令牌，
而不是当作一个风格条目照搬。这两类都不该为了让清单变长而实现。
