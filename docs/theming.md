# Jin（锦）视觉主题规范

> 本文是 Jin 主题的设计规范：视觉层如何落到令牌契约上。组件规范、交互逻辑、API 与状态机不在
> 本文重复（见 [components.md](components.md) 与 [architecture.md](architecture.md)）。这是内部
> 设计文档，面向仓库维护者；应用只是使用者，不需要读它。

主题 id：`data-jin-style="jin"`
模式：`data-jin-mode="dark"` = **玄锦**（标志性模式，库的默认）· `data-jin-mode="light"` = **素锦**

> **来源说明**：**Jin（锦）主题是原创设计**，也是本库的默认视觉风格。
> 另外八个风格（`minimalism-and-swiss-style`、`neumorphism`、`glassmorphism`、`claymorphism`、
> `flat-design`、`neubrutalism`、`brutalism`、`dimensional-layering`）是对
> [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
> 所收录风格的实现——"令牌必须覆盖形状、深度与动效，而不只是颜色"这一要求正是出自该目录。
> 我们实现的是各风格的设计特征，值全部落在本库自己的 80 令牌契约上；该仓库提供的是设计指引而
> 不是 CSS，因此没有复制它的任何样式表。完整署名见 [CREDITS.md](../CREDITS.md)，八个风格各自的
> 定位与所覆盖的契约轴见[第八节](#八已实现风格清单)。

## 一、设计原则

锦的视觉语言 = 经纬网格上的有限色盘 + 丝线光泽 + 金色点缀 + 循环纹样。转译成界面，目标是：
高密度但不杂乱、装饰华丽但有节制、主次层级清晰、织物感但现代可读。

六条原则与它们在令牌/样式里的体现：

| 原则 | 在令牌/样式里的体现 |
| --- | --- |
| 繁而不乱 | 纹样只有一种：8×8 的经纬网格（`--jin-surface-texture`），以极低不透明度出现，且**只允许出现在背景、空状态、装饰性分隔** |
| 有秩序的高密度 | 以 4px 为最小步进的间距刻度；控件高度靠 `--jin-control-height-*` 收紧，**不压缩间距刻度**——压缩间距会缩小触控目标 |
| 边界清晰 | 所有面板都有 1px 边框（`--jin-border-width`），日常边框用中性的经纬线颜色；**金色只用于强边框与焦点环**——处处描金等于没有金 |
| 主次分层 | 地纹→背景、主纹→内容、副纹→次要信息、勾边→强调。对应 `--jin-bg/surface/sunken`、`--jin-text`、`--jin-text-muted`、`--jin-accent`+`--jin-focus-ring-color` |
| 庄重、内敛、精密 | 标题用衬线/宋体（`--jin-font-display`），正文用现代无衬线；圆角 6/8/12px；动效 150–250ms |
| 清晰优先 | 对比度全部实测达标（见第六节），装饰不进入可读区域 |

**明确排除的东西**：它不是"古风皮肤"。没有龙凤、没有祥云满铺、没有书法字、没有金箔贴图。织物感
只由三样东西表达：抽象的经纬网格、细线、克制的色盘与方向性光泽。

## 二、色彩系统

### 有限色盘

不追求连续渐变，只用一组按用途固定的颜色：

| 角色 | 玄锦（深色） | 素锦（浅色） | 用途 |
| --- | --- | --- | --- |
| 地（背景） | `#12171d` 玄青 | `#f5f4f1` 绢白 | 页面底色，只留一丝织物暖意 |
| 面（面板） | `#171e26` / `#1e2731` | `#faf9f6` / `#ffffff` | 层级靠明度差区分 |
| 主纹（强调） | `#e0705a` 朱红 | `#b3402a` 朱红 | 主操作、当前项 |
| 信息 | `#6aa8cd` 石青 | `#2e6386` 石青 | 提示、链接 |
| 成功 | `#6cbd80` 石绿 | `#3f7a4c` 石绿 | 完成、可用 |
| 警告 | `#dda23f` 琥珀 | `#96601a` 琥珀 | 注意 |
| 危险 | `#e2706f` 朱红偏冷 | `#a8323c` 深朱红 | 删除、失败 |
| 金 | `#d8b54a` / `#9a7a14` | `#9a7a14` | **仅**焦点环、强边框、强调装饰 |

### 金色的四条使用规则

金色约占整个界面 5%，**不用于小正文**，只出现在四个地方：

1. **焦点环** `--jin-focus-ring-color` —— 键盘可见焦点的唯一颜色载体
2. **强边框** `--jin-border-color-strong` —— 只在需要勾边强调的地方出现；日常边框
   `--jin-border-color` 是中性的经纬线颜色，不抢视线
3. **装饰性分隔** —— 标签式分隔线两端淡入（`.jin-rule-thread`，或带标签的 `.jin-divider--labeled`）
4. **图标高光** —— 通过 `currentColor` 继承所在位置的用途色，不单独写死颜色

这条规则由脚本强制：`tools/check_tokens.py` 会拒绝任何出现在主题层之外的十六进制颜色。

### 深底用更亮的主纹

深色模式下主纹比浅色模式更亮（`#e0705a` vs `#b3402a`）。浅色模式的 `#b3402a` 放到玄锦的四种表面
上实测只有 2.6–3.2:1：作为按钮填充尚可，作为文字或图标线条则连图形元素的最低对比 3:1 都够不到。
两个模式共用同一套用途命名、取不同的明度——色彩系统必须按模式分别调参，而不是简单反相，
这是其中一条具体原因（另一条见第六节第 1 点）。

## 三、材质与质感

### 丝光（`--jin-surface-gradient`）

柔和、有方向性的光泽：一道自上而下的宽渐变，顶部略亮、底部略暗，模拟光从斜上方来。

```
玄锦：linear-gradient(180deg, rgba(236,234,228,.04) 0%, transparent 40%, rgba(0,0,0,.18) 100%)
素锦：linear-gradient(180deg, rgba(255,255,255,.5) 0%, transparent 40%, rgba(34,32,28,.03) 100%)
```

高光细而窄（40% 处收束），不是大面积发光——丝光的效果是"隐约感到有光泽"，而不是"看见一道光"。

另有按需启用的 `.jin-sheen`：一道 105° 的窄高光在 hover/focus 时扫过一次。它只在交互时播放一次，
不会自行循环；`prefers-reduced-motion` 下高光仍在，只是不再移动。

### 提花浮雕（`--jin-shadow-inset`）

轻微内凹：一道 `inset 0 1px 2px` 的浅内阴影，用于输入框与凹陷区域。不加重阴影，不做旧拟物风的
高光亮边。

### 织纹（`--jin-surface-texture`）

8×8 的经纬网格，SVG data URI，以墨色（浅色模式）/ 米白（深色模式）绘制，约 5% 不透明度。
它只出现在三处：应用显式标注的 `.jin-ground` 区域、空状态/未找到状态的图标底板、装饰性分隔。
**永不进入内容可读区域。**

### 金线 = 三个契约令牌的组合

金线不是一个独立令牌，而是由三个契约令牌组合表达：

- 经纬线 = `--jin-border-color`（1px，中性线色——织物的骨架，不是金）
- 亮金线 = `--jin-border-color-strong`
- 焦点金 = `--jin-focus-ring-color`

分隔线两端淡入的渐变直接引用这三个令牌，所以换主题时金线的色相跟着换。

### 圆角与阴影

| | 值 | 说明 |
| --- | --- | --- |
| 圆角 | 6 / 8 / 12px（sm/md/lg），full = 胶囊 | 现代尺度 |
| 外阴影 | 弥散阴影，按层级加深 | 卡片用 elevation-1，极浅；浮层用 elevation-3/4 |
| 内阴影 | 输入框、凹陷区 | 微浮雕，无高光亮边 |
| `--jin-blur` | `0px` | 显式关闭背景模糊——玻璃质感不属于 Jin |

## 四、纹样、排版、图标、动效

### 纹样系统

只用抽象化、几何化的纹样，且**只实现一种：8×8 经纬网格**。理由：一种纹样做透，比五种纹样互相
打架更接近"繁而不乱"。

主纹/副纹/地纹的层级由**不透明度**区分，不由图案复杂度区分：

| 层级 | 载体 | 强度 |
| --- | --- | --- |
| 地纹 | `--jin-surface-texture` | 5–7% 不透明度 |
| 副纹 | 边框、分隔线 | 34–62% |
| 主纹 | 内容、强调色、焦点环 | 100% |

纹样一律 `aria-hidden`，不进入可访问性树。

### 排版

| 用途 | 令牌 | 字族 |
| --- | --- | --- |
| 标题（弹窗、抽屉、卡片、通知、结果页、警告框标题） | `--jin-font-display` | 宋体/衬线（Noto Serif SC → 宋体 → Georgia） |
| 正文与一切控件 | `--jin-font-family` | 现代无衬线（Inter → 系统 UI → 苹方/微软雅黑） |
| 代码、快捷键 | `--jin-font-mono` | JetBrains Mono → 等宽 |

**分工写在样式表里**：`--jin-font-display` 只挂在真正的标题上。标签页、按钮、表单标签、键值表的
名词都留在无衬线字体——它们要供人快速扫读，效率优先于仪式感。哪些元素算标题无法只用令牌表达，
所以在 `src/styles/jin.css` 的 "titles take the display face" 一节用选择器划分。

字距 `0.012em`、行高 `1.55`，字重只用 400/500/700 三档，避免粗细跳跃。

### 图标

线性、几何、单路径，`stroke` 走 `currentColor`——图标自动继承所在位置的用途色，不硬编码颜色。
图标尺寸以 `em` 为单位，跟随周围文字大小。

### 动效

| 令牌 | 值 |
| --- | --- |
| `--jin-duration-fast` | 150ms |
| `--jin-duration-base` | 200ms |
| `--jin-duration-slow` | 250ms |
| `--jin-easing-standard` | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| `--jin-easing-emphasized` | `cubic-bezier(0.16, 0.84, 0.24, 1)` |

轻、短、克制：不做弹跳、不做旋转、不做夸张缩放。

**两处加载动画是刻意的例外**：spinner 的旋转与骨架屏的扫光使用固定时长，不随主题的时长令牌变化。
理由：旋转时长归零后，转圈图标不再表示"正在工作"，反而丢掉了它唯一的职责。
`tools/check_tokens.py` 把这两处显式列入白名单。

`prefers-reduced-motion: reduce` 下所有时长令牌归零，丝光高光改为静态。

## 五、令牌对应关系

本主题**不新增令牌命名体系**，上述设计意图逐条落在既有的 80 个契约令牌上（完整清单见
[`contracts/tokens.json`](../contracts/tokens.json)）。对照表：

| 设计意图 | 契约令牌 | 说明 |
| --- | --- | --- |
| 地 / 面 / 凹陷 / 抬升 | `--jin-bg` `--jin-surface` `--jin-surface-sunken` `--jin-surface-raised` | 层级主要靠明度差，阴影只做极轻的补强 |
| 正文 / 次要 / 更弱 | `--jin-text` `--jin-text-muted` `--jin-text-subtle` | 三级全部实测 ≥ 4.5:1（见第六节） |
| 强调色上的文字 | `--jin-text-on-accent` | 深色模式下是**深色**文字（见第六节第 1 点） |
| 主色 / 悬停 / 按下 | `--jin-accent` `--jin-accent-hover` `--jin-accent-active` | 按下态只作为填充使用 |
| 四种状态色及各自文字与浅底 | `--jin-danger/warning/success/info` + `-text` + `-bg` | 每色三件套 |
| 经纬线边框 | `--jin-border-color` `--jin-border-color-strong` `--jin-border-width` | Jin 内宽度恒为 1px；金只用于 strong |
| 金色焦点环 | `--jin-focus-ring-color` `-width` `-offset` | **独立成组，不由 accent 推导** |
| 丝光 | `--jin-surface-gradient` | 方向性微渐变 |
| 提花浮雕 | `--jin-shadow-inset` | 内阴影 |
| 织纹 | `--jin-surface-texture` | 经纬网格 data URI |
| 克制圆角 | `--jin-radius-sm/md/lg/full` | 6 / 8 / 12 / 999px |
| 微抬升 | `--jin-elevation-1..4` | 干净弥散阴影，无高光亮边 |
| 无玻璃 | `--jin-blur: 0px` | 显式关闭昂贵效果 |
| 标题字族 | `--jin-font-display` | |
| 正文字族 | `--jin-font-family` | |
| 字距/行高/字重 | `--jin-letter-spacing` `--jin-line-height` `--jin-font-weight-*` | |
| 动效 | `--jin-duration-*` `--jin-easing-*` | |
| 层级 | `--jin-z-*` | |

### 命名只有一套：契约

设计稿阶段的示意命名（`--jin-primary`、`--jin-surface-2`、`--jin-border` 这类）没有进入实现，
全部映射回既有契约名。三个原因：

1. **契约先行**：80 个令牌的名称、用途、类型已经冻结，所有组件与全部主题文件都按它书写。引入
   第二套命名，每个组件都要面对"这个颜色该用 `--jin-primary` 还是 `--jin-accent`"的问题。
2. **脚本可查**：`tools/check_tokens.py` 强制每个主题定义全部令牌、禁止硬编码颜色。多一套命名
   等于放弃这道检查。
3. **多主题共存**：同一个概念在不同叫法下无法互换。`brutalism` 与 `dimensional-layering` 用的
   正是"强调填充 + 其上文字 + 悬停/按下三态"这组契约令牌；保持单一命名，所有主题才能自由切换。

最初的视觉提案（色值、圆角、双层阴影、金色渐变）全部由契约表达；其中金色渐变由
`--jin-border-color-strong` + `--jin-focus-ring-color` 组合得出（见第三节"金线"）。

### 为什么不提供 Tailwind preset

本库不使用 Tailwind，也不产出 preset。原因不是偏好，而是 preset 与令牌契约重复且冲突：

1. **令牌已经是运行时接口**。控件样式全部写 `var(--jin-*)`，主题在运行时通过 `<html>` 上的两个
   属性切换。Tailwind preset 会把颜色在**构建期**固化进类名，换主题就要重新构建——丢掉"切换
   主题 = 改一个属性"这个性质。
2. **会产生第二个事实来源**。同一组色值同时存在于 `contracts/tokens.json`、主题 CSS 和
   `tailwind.config.js` 三处，`check_tokens.py` 只能校验前两处的一致性。
3. **本库不使用它**。样式全部是纯 CSS + 自定义属性，引入 Tailwind 与令牌契约重复。

**如果应用自己用 Tailwind**，正确的接法是把令牌转发成 Tailwind 能引用的运行时变量，而不是把值
复制进去——这样主题切换依然生效：

```js
// tailwind.config.js —— 只转发，不复制色值
module.exports = {
  theme: {
    extend: {
      colors: {
        jin: {
          bg: 'var(--jin-bg)',
          surface: 'var(--jin-surface)',
          text: 'var(--jin-text)',
          accent: 'var(--jin-accent)',
          // …
        },
      },
      borderRadius: {
        'jin-sm': 'var(--jin-radius-sm)',
        'jin': 'var(--jin-radius-md)',
        'jin-lg': 'var(--jin-radius-lg)',
      },
      fontFamily: {
        jin: 'var(--jin-font-family)',
        'jin-display': 'var(--jin-font-display)',
      },
    },
  },
}
```

关键是值写成 `var(--jin-*)` 字符串而不是十六进制字面量。Tailwind 只负责生成 `bg-jin-accent`
这样的类名，真正的颜色仍由主题在运行时决定。

### 如何在本仓库新增一个主题

```css
/* themes/my-style.css —— 必须定义全部 80 个令牌 */
:root[data-jin-style='my-style'] {
  --jin-bg: /* … */;
  /* … 其余 79 个 */
}
```

```bash
python tools/check_tokens.py    # 六项检查（含令牌完整性、无硬编码）
python tools/check_contrast.py  # 对比度审计
```

把文件加入 Gallery 的 `gallery/src/main.ts` 与 `gallery/src/host/preferences.ts`
（`AVAILABLE_STYLES`），顶部切换器里就会出现它。

切换到新风格后，Gallery 的**令牌面板**会逐项显示该风格下的实际取值，任何缺失都会标为
`(missing — fallback in use)`——这是"主题文件是否完整"的可视化证明。面板底部还会渲染
`.jin-ground`、`.jin-sheen`、`.jin-rule-thread` 三个装饰性工具类的实时效果，因为纹样与金线这类
令牌光看数值判断不了视觉效果。

## 六、可访问性视觉

### 实测对比度

下表由 `tools/check_contrast.py` 从 `themes/jin.css` 与 `themes/jin.dark.css` 的令牌值计算，
2026-10（v0.4.0 工作区）复核。脚本随 `pnpm run check` 在每个提交前运行，任何低于阈值的组合
都会让检查失败。

| 检查项 | 玄锦（深色） | 素锦（浅色） | 阈值 |
| --- | --- | --- | --- |
| 正文 on 背景/面板/抬升/凹陷 | 12.6 – 15.6:1 | 13.6 – 16.3:1 | ≥ 4.5 |
| 次要文字 on 四种表面 | 6.6 – 8.2:1 | 5.7 – 6.8:1 | ≥ 4.5 |
| 最弱提示文字 on 四种表面 | 4.8 – 5.9:1 | 4.8 – 5.7:1 | ≥ 4.5 |
| 主色填充 on 四种表面 | 4.8 – 5.9:1 | 4.8 – 5.7:1 | ≥ 4.5 |
| 强调色上的文字 | 4.9:1（按下）– 7.1:1 | 4.9:1（悬停）– 7.1:1（按下） | ≥ 4.5 |
| 焦点环 on 四种表面 | 7.6 – 9.5:1 | 3.4 – 4.1:1 | ≥ 3.0 |
| 四种状态色的文字 on 各自浅底 | 5.9 – 6.3:1 | 6.1 – 7.3:1 | ≥ 4.5 |

### 三个刻意的决定

**1. 深色模式的强调色比浅色更亮，其上文字是深色。**
浅色模式的 `#b3402a` 放到玄锦的四种表面上只有 2.6–3.2:1（第二节），所以深色模式做两件事：把朱红
提到 `#e0705a`，同时把 `--jin-text-on-accent` 从白色改为深色。这是"色彩系统按模式分别调参、不能
简单反相"的具体原因。

**2. 焦点环永远独立声明。**
`--jin-focus-ring-*` 在每个主题文件里都显式定义，绝不由 accent 推导。否则某个把强调色放得接近
自身背景的风格会让键盘焦点几乎看不见——一个由配色选择导致的可访问性失败。Jin 的焦点环用金色：
`#d8b54a`（深色，7.6–9.5:1）与 `#9a7a14`（浅色，3.4–4.1:1）。

**3. 颜色从不作为唯一的信息载体。**
每个 tone 都配独立图标；进度条始终打印百分比；树节点的失败状态同时有图标、文字与重试按钮。

### 其他

- 焦点可见：`.jin-focus-ring` 与各组件的 `:focus-visible` 规则；从不写 `outline: none` 把焦点
  指示抹掉。
- 金色不用于小正文（见第二节）。
- 装饰纹样 `aria-hidden`，不进入可访问性树。
- 默认深色玄锦；浅色素锦为可选模式。

## 七、禁止项（实现中已排除）

| 禁止 | 现状 |
| --- | --- |
| 满屏大红大金、红金渐变、金箔贴图 | 金色限于第二节列出的四处，占比约 5% |

## 八、已实现风格清单

本库发布 9 个风格，每个风格一个浅色文件加一个深色文件；每个文件独立声明全部 80 个契约令牌。
**Jin（锦）是原创**且为默认；另外八个风格是对
[ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 目录条目的实现
（署名见 [CREDITS.md](../CREDITS.md)）。

### 选择标准

该目录共 88 个条目（其中 50 个标记为 active，按 2026-09 选取时的仓库快照）。本批实现的是其中的
**主流风格**：既是业界广泛采用的，也是该目录在自己的 product 与 UX 指引里引用最多的。第二个
条件同样重要——它们覆盖的契约轴互不重叠：`glassmorphism` 是 `--jin-blur` 的唯一使用者，
`neumorphism` 是 `--jin-shadow-inset` 的唯一使用者，`claymorphism` 把"3px 描边 + 大圆角"推到
极限，`brutalism` 与 `flat-design` 分别把动效轴和深度轴归零。一个只换配色、不动形状与深度的
风格，验证不了契约表达的任何一条差异。

### 清单

| 风格 id | 名称 | 圆角 | 深度 | 材质与动效 |
| --- | --- | --- | --- | --- |
| `jin` | 锦（默认） | 6 / 8 / 12px | 弥散阴影 + 内浮雕 | 经纬纹样、丝光渐变、金色点缀 |

### 三条跨风格约定

**1. 深色模式不是浅色模式的反相。** 每个风格的 `.dark.css` 单独调色：深底上的强调色要更亮、
其上文字往往反而要用深色（第六节第 1 点），玻璃与黏土的深色版还要重建光源方向而不是取负。
这也是 `check_contrast.py` 逐文件审计、而不是只审浅色文件的原因。

**2. 半透明表面必须写明它叠在什么底色上。** 玻璃风格的表面写成"深色底上的 rgba"，而不是
"8% 的白"。两者渲染结果相同，但只有前者能被正确测量——白色的 rgba 三元组在任何对比度审计里都
按白色算，算出来的达标不可信。

**3. 浮动层的材质只在一处定义。** 基础样式表把 `--jin-surface-translucent` 与 `--jin-blur` 用在
菜单、浮层、对话框、抽屉、通知这些漂浮在内容之上的表面。非玻璃风格把这两个值与 raised 面板取齐、
blur 设为 `0px`，渲染与没有这两个令牌时完全一致；只有玻璃风格真正需要表达半透明表面。
气泡提示（tooltip）是唯一例外：它用 `--jin-text` 的实色作为底色——小号文字放在半透明深底上，
对比度不可控。

### 未实现的目录分组

Landing Page、BI / Analytics、Mobile 三组描述的是**页面结构与信息密度**（首屏、看板、移动端
导航），不是控件的视觉语言，超出令牌契约能表达的范围。Platform/System 组（Fluent 2、Polaris、
Spectrum 2）本身是一整套设计系统，实现前需要先决定把它的哪一部分映射到这 80 个令牌，而不是
当作一个风格条目照搬。这两类都不以"凑清单数量"为理由实现。
